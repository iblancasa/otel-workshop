Do this **before** the event, on a network you trust. The room will not have
the bandwidth for 30 people pulling images at once.

## Requirements

| Tool | Version | Notes |
|------|---------|-------|
| Docker | any recent | Docker Desktop, Colima, Rancher Desktop or Podman with the docker CLI. Give the VM **6 GB RAM** for this flavour (4 GB runs, with little margin). |
| [kind](https://kind.sigs.k8s.io/docs/user/quick-start/#installation) | >= 0.27 | Kubernetes in Docker. |
| [kubectl](https://kubernetes.io/docs/tasks/tools/) | any recent | |
| make, git, curl | | Already there on macOS and Linux. |

Apple Silicon and Intel both work. Images are built for the machine that
runs `make`. About 3 GB of disk for images, 4 GB of RAM while the cluster
runs.

<Tabs>
  <TabItem label="macOS">
  ```bash
  brew install kind kubectl
  # Docker Desktop: Settings > Resources > Memory >= 6 GB
  # or Colima:
  colima start --cpu 4 --memory 8
  ```
  </TabItem>
  <TabItem label="Linux">
  ```bash
  # kind
  curl -Lo ./kind https://kind.sigs.k8s.io/dl/latest/kind-linux-$(uname -m | sed 's/x86_64/amd64/;s/aarch64/arm64/')
  chmod +x ./kind && sudo mv ./kind /usr/local/bin/kind
  # kubectl: https://kubernetes.io/docs/tasks/tools/install-kubectl-linux/
  ```
  </TabItem>
  <TabItem label="Windows">
  Use WSL2 with Docker Desktop's WSL integration, then follow the Linux
  column inside WSL. Native Windows is untested.
  </TabItem>
</Tabs>

## Prepare

<Steps>

1. Clone, enter the flavour directory, check your tools:

   ```bash
   git clone https://github.com/iblancasa/otel-workshop.git
   cd otel-workshop/cncf
   make check
   ```

   <Terminal src="cncf/check" title="make check" />

   Every `make` command of this workshop runs from `cncf/`. The shop code
   and the Kubernetes manifests of the shop are shared with the otelite
   flavour and live one level up.

2. Build everything. Ten to fifteen minutes depending on your network:

   ```bash
   make prepare
   ```

   This checks tools, pulls the kind node image, the Collector, Jaeger,
   Prometheus, Loki and Perses, builds five small images (frontend, orders,
   inventory, payments, loadgen), creates a kind cluster called
   `otel-workshop-cncf`, deploys the observability stack and the shop. The
   shop is deployed **without** instrumentation. That is step 2.

3. Verify:

   ```bash
   make status
   ```

   <Terminal src="cncf/status" title="make status" />

   Open [localhost:8080](http://localhost:8080) (the shop),
   [localhost:3000](http://localhost:3000) (Perses, the dashboard says *No
   data*), [localhost:16686](http://localhost:16686) (Jaeger, no services
   yet) and [localhost:9090](http://localhost:9090) (Prometheus, only its
   own metrics).

4. Optional, frees memory until the day:

   ```bash
   make down
   ```

   Images stay cached. On the day, `make up` recreates the cluster in about
   a minute with no network at all.

</Steps>

<Aside type="caution" title="No wifi at the venue?">
The speaker brings USB sticks with an image bundle. See
[No wifi](/otel-workshop/cncf/reference/offline/). You still need Docker,
kind and kubectl installed beforehand; those cannot come from a stick.
</Aside>

<Aside type="note" title="Already running the otelite flavour?">
Both flavours map the shop to host port 8080 and the dashboard to 3000, so
only one cluster can be up at a time. `make down` in the other directory
first. Images and build caches are separate per flavour only for the stack;
the five shop images are shared.
</Aside>

## What `make prepare` deploys

```
namespace observability                      namespace shop
  otel-collector   receives OTLP, fans out     frontend   Node.js   :8080 (host)
  jaeger           traces      :16686 (host)   orders     Python
  prometheus       metrics     :9090  (host)   inventory  Java
  loki             logs        :3100  (host)   payments   Python
  perses           dashboards  :3000  (host)   loadgen    background traffic
```

Host ports come from the kind config
([cncf/kind/kind.yaml](https://github.com/iblancasa/otel-workshop/blob/main/cncf/kind/kind.yaml)).
If one of them is taken on your laptop, `make port-forward` is the
fallback.

## Something failed?

See [Troubleshooting](/otel-workshop/cncf/reference/troubleshooting/). The
three usual causes: Docker VM too small (this flavour wants 6 GB), a port
in use, `kind load` choking on a multi-platform image (handled by
`scripts/kind-load.sh`, run `make load`).
