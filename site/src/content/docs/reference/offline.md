Conference wifi fails. Plan for it. Two levels.

## Level 1: attendees prepare at home

This is what the [Prepare](/otel-workshop/prepare/) page asks for. Once
`make prepare` has run once, every image is cached in Docker and the whole
workshop works with the network cable unplugged:

- `make up` recreates the cluster from cached images in about a minute.
- `make instrument`, `make fix`, `make reset` only apply manifests.
- `make rebuild-orders` rebuilds the Python image. Base layers and pip wheels
  are in Docker's build cache from the first build.

## Level 2: USB sticks with an image bundle

For people who did not prepare. Before the event, the speaker runs, with
network:

```bash
make prepare
make bundle                     # bundle/workshop-images-arm64.tar, about 780 MB
```

For a room with both Apple Silicon and Intel laptops, build both:

```bash
make images bundle ARCH=arm64
make images bundle ARCH=amd64   # cross-build, needs buildx/qemu, slow for Java
```

On the stick:

```
usb/
  otel-workshop/                 the repository (zip is fine, .git not needed)
  workshop-images-arm64.tar
  workshop-images-amd64.tar
  README.txt                     generated by make bundle
```

Attendee, no network:

```bash
cd otel-workshop
make load-bundle BUNDLE=/Volumes/USB/workshop-images-arm64.tar
make up
```

`make up` pulls and builds nothing. It creates the cluster from the
`kindest/node:v1.32.2` tag the bundle loaded, loads the other images into it,
and deploys. Pick the right file: `uname -m` says `arm64` on Apple Silicon
and `x86_64` on Intel (use the `amd64` bundle).

Docker, kind and kubectl still have to be installed beforehand. Those cannot
come from a stick in any sane amount of time.

### Step 4 without a build cache

`make rebuild-orders` needs the Python base image and pip wheels. A bundle
attendee never built the image, so the build would need network. Options,
best first:

1. Pair with someone who ran `make prepare`.
2. Skip the rebuild and read the solution. Step 3 and 5 do not need it.
3. Ship the solved image on the stick too:

   ```bash
   # speaker, before the event
   cp solutions/orders/warehouse.py services/orders/warehouse.py
   docker build -t workshop/orders:solved services/orders
   git checkout services/orders/warehouse.py
   docker save -o bundle/orders-solved-arm64.tar workshop/orders:solved

   # attendee, step 4
   docker load -i orders-solved-arm64.tar
   docker tag workshop/orders:solved workshop/orders:latest
   ./scripts/kind-load.sh otel-workshop arm64 workshop/orders:latest
   kubectl -n shop rollout restart deploy/orders
   ```

## This website offline

```bash
make site-build        # site/dist/
npx serve site/dist    # or any static server
```

Put `site/dist/` on the stick as well.

## Sizes

| Item | Size |
|------|------|
| Bundle tar, one architecture | about 780 MB |
| Images loaded in Docker | about 2 GB |
| kind cluster running | 2 to 3 GB RAM |
| Java service | 200 to 400 MB RAM |

Docker Desktop defaults to 2 GB on some installs. 4 GB minimum, 6 GB is
comfortable. Colima: `colima start --cpu 4 --memory 6`.
